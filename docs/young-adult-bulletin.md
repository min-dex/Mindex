# 청년부 주보

폴더 전체 비교 근거: [Archive review (2026-09-23)](young-adult-bulletin-archive-review.md).
72개 PDF에서 확인한 적용 기간·발행 호수·표시 월·예외 일정·테마 변경은 이 조사 문서를 참고한다.
NEXT는 다음 주일을 가리키며, DB에 저장된 집회 없음 상태와 담당자 미정 날짜도 위원표에 유지한다.

2026-09-23 사용자 요청으로 MINDEX에 초기 편집 화면을 반영했다.
청년부 예배 상세의 **주보** 버튼에서 연다. 전용 DB와 발행본 보관은 아직 구현하지 않았다.

## 현재 구현 계약

- `mindex.bulletin.js`가 데이터 해석·SVG 양면 렌더링·내용/양식 편집·인쇄를 담당한다.
  `app.js`는 진입점과 DB 읽기만 연결하고 `styles.bulletin.css`는 편집 화면을 담당한다.
- 저장된 예배 aggregate를 `adopt:false`로 읽는다. Presenter의 미저장 초안이나
  저장 기준을 변경하지 않는다. 찬양·본문·교회력도 DB에서 새로 읽는다.
- 예배 순서·설교 제목·본문·교회 일정·대표기도자와 월간 위원표를 연결한다.
  준비/마침/교제 및 방송용 영상·공백·보조 인용은 제외하고 신앙고백은 순서명만 출력한다.
- 호수·교회명·소식·상시 안내·섬김이·표어·성구·주소·예배 안내·설교 요점과
  프레임 배치는 DB 주소와 예배 ID별 localStorage 초안이다. 기기 간 공유되지 않는다.
  교회명·주소·표어·섬김이·정기 안내는 자료에서 확인한 날짜별 기본값을 사용한다.
  공통 문구 재사용 버튼은 선택 예배일부터 적용되는 기기 내 설정을 저장한다. 직접 수정한 주보 필드는 유지된다.
  기존 광고에 신천지/기도 모임 안내가 포함되면 기본 상시 안내에서 해당 줄을 생략한다. 직접 입력한 안내는 그대로 출력한다.
  자료에서 확인한 2025·2026년 발행일만 호수를 기본 표시하며, 미래 호수는 임의 계산하지 않는다.
  소식은 예배 광고를 기본값으로 사용하고 편집 후에는 로컬 값을 유지한다.
- 내용/양식 모드, 프레임 이동·크기 조정, 정렬, 실행 취소/다시 실행을 제공한다.
  위치와 크기는 2.5 mm 간격, 글자 크기는 7.5/10/12.5/15/17.5/20 pt를 사용한다.
  접지선 148.5 mm 및 그로부터 계산한 폭·중앙 좌표는 실제 종이 규격을 보존한다.
- 교회 일정 월과 위원표 월을 각각 선택한다. 위원표는 해당 월의 모든 주일과 다음 달 첫 주일을 포함한다.
  다음 주일에 NEXT를 표시하며 담당자 없는 날짜는 미정, 저장된 집회 없음은 그 예배의 이름/사유로 표시한다.
- 양식에서 물결·낙엽, 오로라, 사순절, 종려·수난주일, 성령강림주일, 별빛, 흰 바탕, 짙은 테두리 배경과 프레임별 출력 여부를 선택한다.
  모든 이미지 배경은 MINDEX의 기존 `assets/worship-backgrounds/26-*.png`를 직접 재사용한다.
  주보 전용으로 중복 추출했던 WebP 배경 6개는 삭제했다.
  적용 날짜를 추정해 자동 변경하지 않는다. 현재 프레임·로고는 유지하며 과거 주보 전체의 복원을 의미하지 않는다.
- 실제 폰트 로딩과 Canvas 글자 폭 측정을 기다리고 명시적 줄바꿈을 보존한다.
  영역 넘침, 빈 예배 순서, 데이터/자산 로딩 실패 시 인쇄를 막는다.
- 화면의 저장 및 Ctrl/Cmd+S는 로컬 주보 초안만 저장한다. 예배 자료 갱신은
  주보 문구·배치를 유지한다. 예배 원본 수정은 기존 예배 화면에서 한다.
- 인쇄/PDF는 현재 내용을 메모리 안에서 고정한 A4 가로 두 페이지로 만든다.
  브라우저 인쇄 대화상자를 사용하며 DB 발행이나 영구 snapshot 저장을 뜻하지 않는다.
  페이지 바깥 편집 UI는 출력하지 않지만 디자인 안의 흰 패널은 출력한다.
  실제 프린터의 비인쇄 영역과 양면 급지 방향은 장치 설정에 따른다.
- 배경은 기존 `assets/worship-backgrounds/`, RIA 마크만 `assets/bulletin/`을 사용한다. 매주 복제하지 않는다.
  제작·검증 과정에서 중간 HTML/이미지/PDF 파일을 만들지 않는다.

검증: `tests/test_bulletin.cjs`, `tests/smoke_bulletin.cjs`에서 DB 연결 해석,
미저장 Presenter 분리, 로컬 초안 유지, 저장 단축키, 좌표 스냅, undo/redo,
넘침/읽기 실패 차단, A4 양면 PDF를 확인했다. 2026-09-20 실제 저장 자료도
읽기 전용으로 확인했으며 예배 순서 12행과 위원표 5행이 기본 양식에 들어간다.
아래 전용 DB·발행·재사용 설정 등은 후속 설계이며 현재 구현과 구분한다.

## 현재 데이터 원칙

- 예배 순서는 `mindex_worship_elements`의 현재 청년부 예배 항목에서 만든다.
- 대표기도자는 같은 날짜의 `mindex_sunday_calendar.young_adult_prayer`를 우선 사용한다.
- 교회력 값이 아직 없을 때만 현재 예배의 대표기도 항목 담당자를 표시한다.
- 별도 주보 데이터를 `notes`나 `source_ref`에 임의 저장하지 않는다.

## 재개 시 동기화 계약

대표기도자는 교회력이 canonical source다. 주보 기능을 재개할 때
Presenter/예배 편집에서 대표기도자를 바꾸면 교회력도 함께 갱신하는
write path를 Data 영역에서 `young_adult_prayer` 한 곳으로 구현한다. 그
작업이 완료되기 전까지 주보는 교회력 값을 우선 표시해 값이 갈라지지
않게 한다.

## 원본 확인 결과 (2026-09-23)

사용자가 제공한 `청년부 주보 260920 (제26호).idml`과 같은 이름의 PDF를 읽었다.
원본은 OneDrive의 `02_Church/12_주보/04_청년부 주보/청년부 주보 2026`에 있다.
IDML은 약 47.7 MB, PDF는 약 49.5 MB이며 저장소에 복사하지 않았다.
매주 원본 내용을 코드나 seed로 옮기지 않고 템플릿 구조만 구현 대상으로 삼는다.

- IDML 페이지와 PDF 두 페이지 모두 297 × 210 mm인 A4 가로다.
- 중앙을 접는 4면 배치로 보인다. 실물 접지 및 프린터의 양면 방향은 별도 확인한다.
- PDF 1쪽: 왼쪽은 교회 일정·청년부 소식·상시 안내·섬김이 명단, 오른쪽은 표지다.
- PDF 2쪽: 왼쪽은 예배 순서와 인도자, 오른쪽은 예배 위원표·설교 요점·설교 노트다.
- 두 페이지에 물결·낙엽 배경과 흰 패널이 있고, 표지의 RIA 마크 안에도 물결이 보인다.
- 표지는 교회명, 교회력 명칭, 공동체 표어와 성구를 포함한다.
  바깥쪽에는 발행일·호수, 웹사이트·주소, 예배 시간·장소 등의 정보가 배치된다.
- IDML 폰트 목록에는 Freesentation 1–9, Adobe Myungjo Std, Myriad Pro,
  Minion Pro가 있다. 목록만으로 각 글꼴의 실제 출력 사용 여부를 단정하지 않는다.
  PDF 페이지의 폰트 리소스에서는 Freesentation 5 Medium·7 Bold·8 ExtraBold를 확인했다.

### 원본을 반영한 추가 데이터 요구

- 예배 위원표는 당일 대표기도자 한 명뿐 아니라 월간 일정과 다음 달 일부를 표시한다.
  교회력에서 날짜별 담당자를 resolve하고, 표시 기간을 선택할 수 있게 한다.
  `NEXT`는 발행 대상 예배일 이후 다음 주일를 기준으로 계산하여 snapshot에
  저장한다. 열람 당시의 오늘 날짜로 과거 발행본 표시를 바꾸지 않는다.
- 설교 제목과 본문을 예배 순서 및 설교 노트에 함께 사용한다.
  본문의 전체 이름/약칭은 동일한 성경 참조의 표시 형식으로 처리한다.
- 설교 요점 목록은 자유 메모와 구분된 주보 전용 필드로 추가한다.
- 상시 안내, 교회명·주소·웹사이트, 예배 시간·장소, 공동체 표어·성구는 재사용 설정으로
  관리한다. 발행 시 실제 사용한 값도 snapshot에 포함한다.
- 소식은 문장 일부의 굵기 강조가 가능해야 한다. 임의 HTML 대신 제한된 rich text를
  사용하고 목록 번호는 자동 생성한다. 참고 PDF에는 두 소식 모두 ①로 표시돼 있다.
- 배경과 RIA 마크는 별도 템플릿 자산으로 분리하고 한 번 저장한 버전을 재사용한다.
  매주 대형 배경을 Git이나 주보 DB JSON에 중복 저장하지 않는다.

## 화면과 제작 흐름

MINDEX의 Bulletin 진입점에서 주보 목록과 편집 화면으로 이동한다.
예배 상세에는 해당 예배로 주보를 만들거나 연결된 주보를 여는 진입점을 둔다.

1. **초안 생성:** 발행일과 청년부 예배를 선택하고 호수를 입력한다.
2. **자료 확인:** 저장된 예배 순서·설교 제목·본문·찬양·담당자를 불러온다.
   방송용 공백·영상·화면 전환은 자동 인쇄하지 않고, 인쇄할 예배 항목을 선택한다.
3. **주보 편집:** 소식, 교회 일정, 섬김이 명단, 설교 노트 보조 문구를 입력한다.
4. **미리보기:** 편집 영역 옆에 앞·뒷면을 표시하고 필수값 누락과 영역 넘침을 알린다.
5. **발행:** 확인한 내용과 템플릿 버전을 고정하고 PDF를 생성·보관한다.

원본에서 가져온 값에는 출처와 원본 편집 진입점을 제공한다.
설교 제목·본문·담당자의 실질적인 수정은 해당 원본 화면에서 한다.
주보 안에서는 항목 표시 여부와 인쇄용 줄바꿈 등 표현만 조정한다.

## 데이터 연결과 갱신

| 주보 내용 | 원본 또는 소유 영역 | 편집 규칙 |
| --- | --- | --- |
| 예배 순서·설교·찬양 | 연결한 예배와 Praise/Scripture | 저장된 원본을 읽고 인쇄용으로 구성 |
| 대표기도자 | 같은 날짜의 교회력, 없을 때 예배 담당자 | 기존 canonical source 규칙 유지 |
| 교회 일정 | 기존 일정 중 사용자가 선택한 항목 | 연결할 원본 구조 확인 후 구현, 주보 전용 추가 문구는 구분 |
| 호수·발행일·소식·명단·보조 문구 | Bulletin | 주보 초안에서 편집 |
| 용지·배치·타이포그래피 | Bulletin template | 버전별 고정 |

초안 생성 시 저장된 원본을 resolve하여 작업용 사본과 출처 정보를 보관한다.
원본이 달라지면 변경 표시와 비교 화면을 제공하고, 사용자가 갱신하면 연결 내용을
다시 불러온다. 입력 중인 주보 전용 문구는 유지한다. 이 사본은 원본의 새 canonical
source가 아니며, 주보 편집이 예배나 찬양 데이터를 덮어쓰지 않는다.

발행 직전 원본 변경 여부를 다시 확인한다. 변경된 원본을 반영하거나 현재 사본을
유지할지 명시적으로 선택한 후 확정한다. 비교한 원본 revision 또는 fingerprint를
기록한다. 저장되지 않은 Presenter 초안이나 슬라이드 캐시는 자료로 사용하지 않는다.

대표기도자 동기화 write path는 위 계약대로 별도 구현한다. 그전에는 주보에서
대표기도자를 직접 수정하지 않고 교회력 값을 우선 표시한다.

| `mindex_bulletins` | 주보 ID, 예배 ID, 발행일, 호수, 템플릿 버전, 초안 revision, 주보 전용 content, 작업용 resolved content, 출처 정보, 최신 발행본 ID |
| `mindex_bulletin_templates` | 템플릿 ID·버전, 용지 규격, 영역 정의, renderer 버전, 고정 자산 참조 |
| `mindex_bulletin_editions` | 주보 ID, 발행 차수, immutable snapshot, 템플릿·renderer 버전, PDF 참조, 생성 상태, 발행 시각 |

주보 전용 content는 버전이 명시된 JSON 구조로 시작한다. 소식·일정·명단은 안정적인
항목 ID와 정렬 순서를 갖는다. 기존 Worship의 `notes`나 `source_ref`에 저장하지 않는다.
템플릿 버전과 발행 차수에는 각각 중복 방지 제약을 둔다.

초안 저장은 revision을 이용한 optimistic concurrency를 적용한다.
다른 사용자가 먼저 저장했다면 덮어쓰지 않고 비교 후 다시 저장하게 한다.
접근 권한은 기존 MINDEX 운영 권한에 맞추며 새 테이블과 PDF 저장소의 RLS/정책을
함께 정의한다. 미발행 초안이 공개 다운로드 경로에 노출되지 않게 한다.

## 발행과 재발행

발행본 snapshot에는 실제 출력 문구, 선택한 순서, 인쇄용 표현 설정, 템플릿 버전,
출처 ID 및 revision/fingerprint를 담는다. 이미지가 있다면 변경 가능한 URL만 남기지
않고 버전이 고정된 자산을 참조한다. 이미 발행한 PDF는 보관된 파일을 다시 내려받는다.

발행 요청 시 서버에서 초안 revision을 검증하여 snapshot과 `pending` 발행 레코드를
확정한다. PDF는 그 snapshot만으로 생성한다. 파일 저장과 검증까지 성공하면
`published`로 전환하고 최신 발행본 포인터를 갱신한다. 실패하면 초안과 이전 발행본을
유지하며 실패 상태를 표시한다. 같은 요청 ID의 재시도는 같은 발행 레코드를 사용한다.
DB와 파일 저장은 단일 transaction이 아니므로 부분 실패와 응답 유실 복구를 구현한다.

발행본을 수정하지 않는다. 수정은 새 초안 revision에서 진행하고 같은 주보의
새 발행 차수로 재발행한다. 이전 snapshot과 PDF도 그대로 보존한다.

## 출력 구현 방향

템플릿의 물리 단위와 고정 글꼴을 사용하는 인쇄 전용 HTML/CSS renderer를 둔다.
미리보기와 PDF는 같은 resolved content와 템플릿을 사용한다.
Electron에서는 PDF 출력 API를 이용하는 방안을 먼저 검증한다.
웹에서는 동일한 PDF를 만들고 보관할 생성 경로가 추가로 필요하므로,
브라우저 인쇄 대화상자만으로 발행 성공을 판정하지 않는다.

문구가 영역을 넘치면 어느 항목인지 표시하고 발행을 막는다.
글자를 임의로 줄이거나 페이지를 자동 추가하지 않는다.
용지 규격 확정 후 앞·뒷면 순서와 양면 인쇄 방향을 실제 출력으로 확인한다.

## 구현 순서와 완료 조건

1. 원본 IDML/PDF를 확인하고 고정 템플릿과 예배→인쇄 항목 mapping을 확정한다.
2. Bulletin 저장 구조·권한·revision 및 저장된 원본을 읽는 resolver를 구현한다.
3. 초안 편집, 원본 변경 비교, 앞·뒷면 미리보기를 연결한다.
4. snapshot 발행, PDF 생성·보관, 재시도와 재발행을 구현한다.

MVP 완료는 다음 실제 흐름으로 확인한다.

- 예배 선택 시 저장된 자료가 채워지고, 교회력의 대표기도자가 우선 표시된다.
- 지난주 복사 시 새 예배 자료를 불러오고 주보 전용 내용만 이어받는다.
- 원본 갱신 시 주보 소식이 보존되며, 동시 저장 충돌은 조용히 덮어쓰지 않는다.
- 긴 소식의 넘침을 감지하고, 확정 규격의 양면 PDF에서 한글·줄바꿈·배치를 확인한다.
- 발행 후 원본이나 템플릿을 수정해도 기존 snapshot과 PDF가 바뀌지 않는다.
- PDF 생성 실패·저장 실패·응답 유실 후 재시도해도 중복 발행하지 않는다.

## 2026-09-23 원본형 배치 보정

9/20 PDF의 텍스트 좌표·폰트 크기를 비교해 기본 프레임을 보정했다.
일정/위원표 월 표시는 우상단에 분리하고, 환영 문구는 소식 제목 옆에 배치한다.
소식·상시 안내는 번호/기호와 본문을 분리하며, 섬김이는 직책·이름의 2열×3행으로 표시한다.
예배순서 명칭은 균등 자간, 찬양 블록의 명칭/담당자는 세로 중앙, 순서는 사용 가능한 높이에 분산한다.
위원표는 홀수 개일 때 왼쪽보다 오른쪽에 한 항목을 더 두고 날짜/이름 양끝 정렬 및 별도 NEXT 배지를 쓴다.
표어·성구·상하단 글자 크기와 위치, 노트 줄도 원본에 가깝게 조정했다.

기존 사용자가 조정한 프레임은 보존한다. **양식 → 원본형 양식 적용**으로 새 기본 배치를 적용하며
문구는 유지되고 실행 취소할 수 있다. 과거 저장 초안은 이 버튼을 눌러야 새 좌표를 완전히 적용한다.
DB 광고의 환영/정기 안내는 각 인쇄 영역으로 나누되, 원문 DB는 변경하지 않는다.
교회력에 없는 시간·행사나 DB에 없는 담당자/설교 요점은 임의 생성하지 않는다.
교회 일정은 DB를 기본값으로 읽고 주보용 문구를 수정할 수 있으며 수정본은 기기 내 초안이다.
